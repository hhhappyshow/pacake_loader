# S20 浏览器实时三维查看器

在当前恢复工作区运行：

```bash
cd /home/zhong/pacake_loading/shiki
./s20-view
```

浏览器打开 http://127.0.0.1:8765，默认选择 **实物 14 箱 · 三列四层 + 翻转两箱**，点击 **开始 12 + 2 箱仿真**；下拉菜单也可选择原有空舱翻转或四箱流程。端口被占用时使用 `./s20-view --port 8766`。

- 左键旋转、右键平移、滚轮缩放；提供透视、正视、俯视。
- 舱壁可切换半透明，显示 TCP 轨迹、关节角度、动作阶段、完成箱数。蓝色箭头表示吸盘朝向，侧栏实时显示它与水平面的夹角。
- **冻结画面只冻结三维显示，仿真仍继续**；恢复后跳到最新状态。
- 停止仿真发送中断信号，保留已有轨迹；后台规划退出可能需要一点时间。
- 每次开始均创建新的 `runs/browser_时间戳/`，对应日志为相邻的 `.log`。
- 服务只监听本机，启动命令固定为 `s20-contact-sim`，不调用任何真机或 IO 接口。
- 新模式在已有三层箱子的场景中新增一箱；原有翻转模式为空舱单箱。均使用理想刚性吸附和冻结释放，不包含接触动力学或吸力验证。

## 原理

`four20_sparse_cycle.py --browser-stream` 在模型建立后一次性导出 `web/scene.json` 和 `web/geometry.bin`。显示几何取自 Newton 当前模型，包括 CAD 网格和箱体碰撞包络；不使用简化骨架替代机械臂。

运行中最多约 20 Hz 原子更新 `web/state.json`，包含 Newton 的世界位姿 `body_q`（位置 + xyzw 四元数）、关节角与阶段。浏览器以各刚体为父节点，把 shape 的局部位姿组合上去。尚未到达的箱子被隐藏。服务器不重复加载不断增大的轨迹文件。

Three.js 0.160.1 与 OrbitControls 已保存在 `vendor/`，MIT 许可见 `vendor/THREE-LICENSE.txt`，运行时无需访问 CDN。前端使用浏览器 WebGL，不使用 Newton 的 OpenGL 渲染器；仿真仍使用原 Python 虚拟环境，自动选择 CUDA 或 CPU。

如要从命令行向其他查看程序提供实时数据，在原仿真命令增加 `--browser-stream --realtime --saved-camera-only`。`--saved-camera-only` 避免运行中重复渲染相机，不影响各轮感知。

## 故障排查

- 首次运行需要加载模型、YOLO 和规划器，请等待状态从“初始化中”变为“实时运行”。
- 规划阶段机械臂可能静止；页面显示最近状态的时间，不能把所有静止都视作卡死。
- WebGL 创建失败：在支持 WebGL 的桌面浏览器中打开，检查浏览器硬件加速设置。
- 初始化失败或中途出错：页面显示错误；查看本次 `.log` 获取完整原因。
- 服务进程关闭后网页失去连接；重新执行 `./s20-view`。服务本身不恢复上一次会话。

## 翻转与水平插入

流程为：顶部抓取 → 抬升并移至舱外安全位置 → 吸盘转向水平、朝向舱内 → 保持朝向直线插入 → 下降放置 → 沿吸盘反方向退吸 → 空载返回观察位。

这里的“水平”按世界重力方向定义。集装箱本身稍有倾斜，规划器先将舱内方向投影到世界水平面，再计算 TCP 朝向；根据实际吸附变换更新箱体包络，不能简单交换箱子的长和高。翻转时采用整个箱体的扫掠范围选择舱外旋转点。原有 CAD 碰撞检查保留，并增加水平误差不超过 1°、直线路径误差不超过 5 mm、翻转箱体离舱口至少 10 mm 的限制；执行前用实际吸附关系重新检查。

命令行复现（在 shiki 目录）：

```bash
experiments/s20_online_mixed8_20261024/s20-contact-sim \
  --arrivals one20 --placement-mode flip-horizontal --size-noise 0 --planning-mode async \
  --weights experiments/s20_online_mixed8_20261024/perception/weights/yolo11m-seg.pt \
  --pose-json runs/observe_moved_box_attempt1/controller_snapshot.json \
  --waypoints experiments/s20_online_mixed8_20261024/deployment/pick_waypoints.json \
  --site-urdf experiments/s20_online_mixed8_20261024/deployment/site_robot.urdf \
  --record-decisions --output runs/my_flip_test
```

运行完成后审计实际记录的轨迹（替换运行目录）：

```bash
reproductions/nvidia_curobo_v2_20261023/.venv/bin/python \
  experiments/s20_online_mixed8_20261024/straight_place/audit_flip.py runs/my_flip_test
```

结果保存为运行目录中的 `flip_acceptance.json`。`runs/flip_checked_06` 的验证结果：完成 1/1 并返回；插入时吸盘最大水平误差 0.000542°，直线偏差 0.0683 mm，翻转期间箱体距离舱口至少 167.9 mm，箱体原顶面法向实际转动 89.43°。释放后最低角点高于舱底约 2.69 mm；这是几何检查结果，不代表动力学落稳。

## 三层堆叠：宽边竖直、长边水平

新模式参数为 `--arrivals one20 --placement-mode stacked-width`。将上方复现命令中的 `flip-horizontal` 改为 `stacked-width`，并选择一个新的输出目录即可。查看器里直接选择“三层堆叠 · 宽边竖直插入”。当前新版验证服务使用 8766 端口；也可重新启动服务使用默认 8765 端口。

轴定义：箱子本体 X 是长边 55 cm，Y 是宽边 40 cm，Z 是厚度 25 cm。目标是 X 水平、Y 竖直，吸盘 +Z 水平指向舱内。显示中的红箭头表示长边、绿箭头表示宽边、蓝箭头表示吸盘方向；侧栏显示各自的角度误差。

场景使用已知的示例布局：每层 2×3 个箱子，共 18 个，三层总高 75 cm；布局定义在 `straight_place/stacked_scene.py`。这是仿真用任务先验，并非对实际集装箱货物的测量。所有预置箱子都加入原 CAD/FCL 碰撞模型，保留现场集装箱模型及顶盖，并参加目标支撑和通道检查。

规划在接触箱子之前完成：

1. 对吸盘及支架完整包络能容纳的抓取朝向，分别预检接近、吸取、抬升与搬运。
2. 每个抓取候选继续求解宽边竖直的舱外调整、水平插入、放置及空载退出；拒绝无法完成整个流程的候选。
3. 在可行候选中按总关节路径长度选择，随后执行。这里是有限抓取与路径候选的比较，不是连续空间全局最优规划。
4. 执行前根据实际吸附变换复核整条放置路径，执行抓取搬运时继续逐段检查实际状态。

新模式跳过原固定“舱口示教点”，因为携带箱子经过该点会与第三层发生碰撞；从抬升点开始直接规划舱外调整。最终朝向是规划输入，进入舱内前已经完成调整。每 20 ms 的原 CAD 碰撞检查保留，并约束吸盘水平误差不超过 1°、宽边竖直与长边水平误差不超过 2°。

`runs/stack_width_03` 完整流程与实际轨迹验收通过：宽边离竖直约 0.80°，长边离水平约 0.47°，吸盘插入水平误差约 0.0003°；箱体与顶盖的插入最小几何间隙约 28.2 cm。比较了 0° 和 180° 两种完整包络可容纳的抓取朝向，选择 180°，总关节路径长度由约 18.56 降至 18.15 rad（各段六维关节增量的欧氏长度之和）。冻结释放后箱体最低点离第三层顶面约 15.6 mm，尚未模拟重力落稳或箱体接触变形。

## 连续翻转装四箱

选择“三层堆叠 · 连续翻转装四箱”，会保留原有三层 18 箱，再依次抓取、翻转并放入 4 个 55×40×25 cm 箱子。原单箱模式仍可选择。命令行在上方命令中使用 `--arrivals four20 --placement-mode stacked-width`，输出目录换为新的名称。

每轮重新观察当前箱子并比较抓取方案，向规划进程传递前面所有已放箱子的实际冻结位姿和保守占用包络。候选位置按深处优先搜索；退吸后先沿水平通道退出，再调整空载姿态。整个持箱、插入及退出过程仍使用原 CAD 碰撞检查。

查看器在抓取前显示“第 N 箱：检查抓取与装箱路径 X/Y”，避免把计算等待误显示成持续调整视角。每轮的抓取比较记录保存在 `grasp_plan_search_by_cycle`；`audit_flip.py` 会逐箱检查方向、直线偏差、舱外翻转距离、顶盖间隙、返回及释放后的位姿保持。

已验证运行：`runs/flip_four_verified_05`，4/4 完成并返回。四箱实际宽边竖直误差分别约 0.803°、0.746°、0.692°、0.802°；箱体插入时顶盖最小间隙均超过 28 cm。第三箱触发实际吸附碰撞复核拒绝并成功重新规划，其余三箱使用复核通过的后台路径。冻结释放仍保留约厘米级几何间隙，没有接触动力学落稳。具体逐箱结果见该目录的 `flip_acceptance.json`。


## 实物 14 箱：12 箱预置 + 2 箱翻转（2026-11-18）

打开查看器的「查看 14 箱摆放图与人工摆放顺序」链接，或 `/layout14.html`。图中有逐箱底角坐标、方向、尺寸和人工顺序；机器可读导出为 `straight_place/stack14_layout.json`。

- 底层最长边沿舱深、最短边竖直；从舱口看右/中/左三列，自下而上分别是 3→4→1→11、8→10→2→12、9→5→7→6。顶面高 99/99/97 cm。
- 底箱前沿距舱口最小 5 cm。12 箱全部经过舱内边界、相互碰撞和完整底面支撑验证。
- 待放箱按用户指定次序为 35×23×54、36×23×54 cm；抓取前高 23 cm，翻转后高 35/36 cm，长 54 cm 横向。
- 两个目标标称底角（深、横向、高）为 (42.5,24,99)、(16.5,24,99) cm，先深后浅；共同由底箱 11、12 支撑。标称投影支撑率 96.3%，中心位于实际支撑区域。此值不是承重或变形验证。
- 新模式以 `FLIP_COUPLED_OUTSIDE` 代替单独的 lateral clearance + 原地翻转。以当前关节状态为起点选择有效 IK 终点，同步插补多个关节，逐样本检查原始 CAD 和附着箱体舱外余量。单次耦合翻转每关节位移上限 120°。
- 整个新模式要求距 URDF 限位至少 15°，采样速度 ≤25°/s、加速度 ≤50°/s²。每段使用平滑时间缩放并在段端停止；不声称全局最优或硬件控制器已验证。
- RGB-D/YOLO 仍用于定位；本模式尺寸来自用户测量和指定到箱顺序，**不是 YOLO 自动量出的尺寸**。

命令行：沿用本页站点、权重、初始点参数，将模式设为 `--arrivals two14 --placement-mode stacked14`。此模式与旧四箱/旧堆叠模式独立，未接入实机执行入口。

验证记录：`runs/stack14_verified05` 完成 2/2 并返回，`flip_acceptance.json` 通过全部几何和关节采样审计。最小关节限位余量 17.09°，峰值速度 24.30°/s、加速度 47.96°/s²，顶盖最小余量 8.39 cm；第一箱翻转 J4/J5/J6 累计 94.49°/75.90°/78.42°。普通直立单箱回归 `runs/stack14_upright_regression` 完成 1/1。

限制：运动学仿真仍是理想刚性吸附、冻结释放；实际记录的释放底角比支撑面高约 1.4–1.5 cm，未验证真实落稳、纸箱变形、吸力或负载。因此摆放图是现场布置基准，不是可直接执行的实机轨迹。
